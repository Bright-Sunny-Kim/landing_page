# Google Drive 디렉터리 정리 방안

## 1. 목적

현재 Google Drive에 축적된 업무, 강의, 연구, 데이터 분석 및 개인 자료를 일관된 기준으로 정리하고, 향후 `landing_page` 웹사이트와 Ubuntu 서버로 이전하기 쉬운 구조를 만드는 것이 목적이다.

## 2. 현재 구조 요약

확인된 최상위 구조는 다음과 같다.

```text
My Drive
├─ 01_WORK
│  ├─ 01_AUDIT
│  ├─ 02_TAX
│  ├─ 03_CONSULTING
│  ├─ 04_사무실운영
│  ├─ 04_MY_INFO
│  └─ 99_ARCHIVE
├─ 02_USW_경영공학대학
│  └─ 연도별 폴더
├─ 03_DATA_ANALYSIS
│  └─ 데이터 분석·AI·자동화 도구별 폴더
├─ 06_카카오톡으로받은파일
├─ 99_ARCHIVE
└─ 루트에 개별 문서 및 Colab 파일
```

## 3. 주요 개선점

### 3.1 수신 자료를 임시 보관함으로 관리

`06_카카오톡으로받은파일`에는 고객, 업무, 연도와 관계없이 PDF, HWP, XLS, XLSX, DOCX, ZIP 등이 혼재되어 있다. 이 폴더를 영구 저장소로 사용하지 않고 `00_INBOX`로 변경한다.

`00_INBOX`의 파일은 다음 상태 중 하나를 가져야 한다.

- 미분류
- 검토 중
- 업무 폴더로 이동 완료
- 중복
- 폐기 대상

매주 또는 매월 정리하여 장기간 남아 있는 파일이 없도록 한다.

### 3.2 분류 기준 통일

현재 업무 종류, 연도, 기술 주제, 수신 경로, 보관 상태가 같은 계층에 섞여 있다. 최상위 폴더는 자료의 용도 기준으로 고정하고 연도, 고객, 프로젝트 등은 하위 계층에서 사용한다.

### 3.3 명칭과 번호 규칙 통일

- 최상위 번호는 중복하지 않는다.
- 한글과 영문 중 하나를 주 명칭으로 정하고 필요하면 괄호에 보조 명칭을 표시한다.
- 폴더명에 공백, 특수문자와 불필요한 약어를 줄인다.
- `수정`, `최종`, `진짜최종`, `(1)` 대신 버전과 상태를 명시한다.

### 3.4 보관함 통합

루트 `99_ARCHIVE`와 `01_WORK/99_ARCHIVE`를 하나의 정책으로 통합한다. 보관 자료도 업무, 강의, 지식, 시스템 영역을 유지하여 나중에 검색할 수 있게 한다.

### 3.5 민감자료 분리

계좌내역, 사업자등록증, 인증서, 감사조서 및 세무자료는 일반 강의·연구 자료와 분리하고 공유 권한을 최소화한다. 인증서와 비밀번호는 일반 Drive 폴더가 아니라 별도의 비밀관리 시스템을 사용하는 것이 바람직하다.

## 5. 업무 및 강의 폴더의 표준

### 업무

```text
10_BUSINESS/audit/2026/고객코드_고객명/
├─ 00_ADMIN
├─ 10_RECEIVED
├─ 20_WORKING
├─ 30_REVIEW
├─ 40_DELIVERED
└─ 90_CLOSED
```

### 강의

```text
20_EDUCATION/usw/2026/1학기_과목코드_과목명/
├─ 00_ADMIN
├─ 10_SYLLABUS
├─ 20_LECTURES
├─ 30_ASSIGNMENTS
├─ 40_EXAMS
├─ 50_STUDENT_MATERIALS
└─ 90_ARCHIVE
```

학생 개인정보와 제출물은 공개 강의 콘텐츠와 반드시 분리한다.

## 6. 파일명 규칙

일반 문서:

```text
YYYY-MM-DD_고객코드_업무유형_문서종류_상태_vNN.ext
```

예:

```text
2026-07-30_HYEAN-A001_감리_사전자료요청_원본_v01.pdf
2026-07-29_KRIS-C001_기업진단_보고서_확정_v01.pdf
```

강의 자료:

```text
YYYY_학기_과목코드_주차_주제_유형_vNN.ext
```

상태는 `원본`, `초안`, `검토중`, `확정`, `제출본`처럼 제한된 용어만 사용한다.

## 7. 정리 실행 순서

1. 전체 파일 목록과 공유 권한을 추출한다.
2. 파일 ID, 경로, 형식, 크기, 수정일을 기록한다.
3. 동일한 체크섬을 가진 중복 파일을 찾는다.
4. `06_카카오톡으로받은파일`을 `00_INBOX`로 전환한다.
5. 고객 및 프로젝트 코드를 정의한다.
6. 현재 진행 중인 1개 업무를 표준 구조로 시범 정리한다.
7. 강의 1개 과목을 표준 구조로 시범 정리한다.
8. 검증 후 나머지 폴더에 순차 적용한다.
9. 완료된 자료는 통합 `99_ARCHIVE` 정책에 따라 보관한다.

## 8. 운영 원칙

- Google Drive는 원본 수신과 외부 협업을 위한 보조 저장소로 사용한다.
- 업무 상태와 권한의 기준 정보는 향후 웹 시스템의 DB에서 관리한다.
- 파일 이동 전에는 전체 인벤토리와 백업을 생성한다.
- 삭제는 중복 및 보존기간 검토 후 별도 승인 절차로 수행한다.
- 공유 링크와 사용자 권한을 정기적으로 점검한다.
